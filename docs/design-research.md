# 점심 추천 서비스 디자인 리서치

## 목적

현재 앱은 기능적으로는 점심 메뉴를 고를 수 있지만, 첫인상이 “가볍고 재밌는 점심 결정 앱”보다 “사내 관리자 페이지”에 가깝다. 다음 개편의 목표는 예쁜 화면을 덧칠하는 것이 아니라, 사용자가 10초 안에 오늘 상태를 고르고 메뉴를 확정하는 흐름을 더 또렷하게 만드는 것이다.

이 문서는 웹/모바일 UI 리서치, HCI 논문, 디자인 시스템 가이드, 레퍼런스 사이트를 기반으로 다음 디자인 작업의 기준을 정리한다.

## 핵심 결론

1. 첫 화면에서 사용자가 해야 할 행동은 하나여야 한다.
   - 지금은 “오늘 상태 고르기”, “다른 메뉴”, “기록”, “필터 칩”, “추천 카드”가 동시에 경쟁한다.
   - 모바일에서는 특히 `오늘 상태 고르기` 또는 `아무거나` 중 하나가 첫 행동으로 보여야 한다.

2. 추천 앱의 중심은 리스트가 아니라 “결정 카드”다.
   - 이 앱의 핵심 경험은 많은 메뉴를 둘러보는 것이 아니라 “오늘 뭐 먹지?”를 빠르게 끝내는 것이다.
   - 화면 중심에는 메뉴명, 음식 감각 키워드, 결정 버튼이 있어야 한다.

3. 상태 선택은 숨은 설정이 아니라 추천의 시작점이다.
   - `매운 걸로`, `해장 필요`, `다이어트`, `법카` 같은 선택은 단순 필터가 아니라 앱의 재미다.
   - 상태 선택 UI는 버튼 묶음보다 “오늘의 기분 카드”나 바텀시트가 더 적합하다.

4. 데이터 신뢰감을 화면에서 보여줘야 한다.
   - “왜 이 메뉴인지”를 긴 설명으로 보여주기보다 `해장 + 국물 + 중식 조건에 맞음`처럼 짧은 근거 태그로 보여주는 편이 낫다.
   - 개인 기록과 지역 통계는 보조 정보로 두되, 추천 결정 흐름을 방해하지 않아야 한다.

5. 디자인은 장식보다 위계가 먼저다.
   - Figma와 NN/g 모두 시각 위계, 일관성, 간결함을 핵심 원칙으로 본다.
   - 지금은 카드와 버튼이 비슷한 무게로 반복되어 화면의 “주인공”이 약하다.

## 근거 자료

### UX / HCI 원칙

- NN/g, 10 Usability Heuristics
  - 핵심: 시스템 상태를 즉시 알려주기, 현실의 언어 쓰기, 불필요한 정보 줄이기, 사용자가 쉽게 되돌릴 수 있게 만들기.
  - 적용: 추천 결과가 바뀌면 “어떤 조건 때문에 바뀌었는지” 즉시 보여준다. `후보`, `판결 이유`처럼 내부자스러운 말은 줄인다.
  - https://www.nngroup.com/articles/ten-usability-heuristics/

- NN/g, Aesthetic-Usability Effect
  - 핵심: 사용자는 보기 좋은 인터페이스를 더 사용하기 쉬운 것으로 인식한다. 다만 예쁨이 큰 사용성 문제를 덮지는 못한다.
  - 적용: 단순히 색과 radius를 바꾸는 것이 아니라 행동 흐름까지 정리해야 한다.
  - https://www.nngroup.com/articles/aesthetic-usability-effect/

- Lindgaard et al. (2006), Attention web designers: You have 50 milliseconds to make a good first impression
  - 핵심: 웹 페이지의 시각적 첫인상은 매우 짧은 시간에 형성된다.
  - 적용: 첫 뷰에서 브랜드, 음식, 행동이 바로 읽혀야 한다. 설명 문장이나 보조 패널이 먼저 보이면 손해다.
  - https://www.tandfonline.com/doi/abs/10.1080/01449290500330448

- Tractinsky, Katz, Ikar (2000), What is beautiful is usable
  - 핵심: 미적 인상이 사용성 인식에 강하게 영향을 준다.
  - 적용: 추천 알고리즘이 좋아져도 화면이 딱딱하면 사용자는 “그냥 랜덤 앱”으로 느낄 수 있다.
  - https://cris.bgu.ac.il/en/publications/what-is-beautiful-is-usable-2/

- Lavie & Tractinsky (2004), Assessing dimensions of perceived visual aesthetics of web sites
  - 핵심: 웹 미감은 정돈감, 명료성 같은 고전적 미감과 창의성, 독창성 같은 표현적 미감으로 나뉜다.
  - 적용: 우리 앱은 정돈감은 어느 정도 있으나 표현적 미감이 약하다. 음식, 점심, 친구 같은 정서가 더 필요하다.
  - https://doi.org/10.1016/j.ijhcs.2003.09.002

### 모바일 / 접근성

- WCAG 2.2 Target Size Minimum
  - 핵심: 포인터 입력 대상은 최소 24x24 CSS px 이상이어야 하며, 충분한 간격도 중요하다.
  - 적용: 모바일 칩, 아이콘, 메뉴 항목은 눌리는 영역을 넉넉하게 잡는다.
  - https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html

- Apple Human Interface Guidelines
  - 핵심: 명확한 위계, 플랫폼 관습, 화면 크기 변화에 맞는 일관성을 중시한다.
  - 적용: 모바일은 웹의 축소판이 아니라 별도 행동 구조가 필요하다. 큰 CTA, 안전한 여백, 손가락 기준 배치를 우선한다.
  - https://developer.apple.com/design/human-interface-guidelines/

- Material Design
  - 핵심: 색, 타이포그래피, 접근성, 컴포넌트 상태를 시스템으로 다룬다.
  - 적용: 지금처럼 CSS 값이 화면마다 흩어지는 대신 색/공간/타입 토큰을 먼저 잡고 컴포넌트를 맞춘다.
  - https://m3.material.io/

- Baymard, Button Design
  - 핵심: 모바일 버튼은 크기, 색, 배치, 문구가 모두 행동 유도에 영향을 준다. 주요 버튼은 다른 버튼과 뚜렷하게 구분되어야 한다.
  - 적용: `오늘 상태 고르기`와 `다른 메뉴`가 같은 무게로 보이면 사용자는 앱이 원하는 행동을 모른다.
  - https://baymard.com/learn/button-design

- Baymard, Mobile Filter UI
  - 핵심: 모바일 필터는 사이드바보다 전체 화면 또는 바텀시트가 적합하며, 명확한 적용 CTA와 활성 필터 표시가 필요하다.
  - 적용: 오늘 상태 선택은 모바일에서 바텀시트로 열고, 선택 후 메인 카드에 활성 조건을 압축해서 보여준다.
  - https://baymard.com/learn/ecommerce-filter-ui

### 제품 지표와 데이터

  - 핵심: UX를 Happiness, Engagement, Adoption, Retention, Task Success로 측정한다.
  - 적용: 이 앱은 “추천 정확도”만 볼 게 아니라 `상태 선택률`, `메뉴 확정률`, `다음날 재방문`, `오늘은 아님 비율`을 같이 봐야 한다.

## 현재 앱 진단

### 1. 첫 화면 위계가 흐림

문제:
- 오늘 상태, 다른 메뉴, 프로필, 필터 칩, 추천 카드, 기록이 모두 비슷한 힘으로 보인다.
- 사용자가 “먼저 뭘 해야 하지?”를 생각해야 한다.

개선:
- 첫 화면의 주인공을 `오늘 상태 고르기` 또는 `오늘 메뉴 카드` 하나로 정한다.
- 보조 기능은 접거나 아래로 내린다.
- 모바일에서는 하단 고정 액션바를 두고, 주요 CTA 하나만 강하게 둔다.

### 2. 디자인 언어가 서비스 성격과 맞지 않음

문제:
- 굵은 테두리, 반복 카드, 관리자형 사이드 패널 때문에 사내 도구처럼 느껴진다.
- 음식 앱인데 음식의 색, 질감, 감각이 적다.

개선:
- 음식 키워드와 짧은 카피를 카드의 핵심 요소로 둔다.
- “오늘 점심 결정”이라는 순간의 가벼움과 재미를 살린다.
- 판결소 콘셉트는 유지하더라도 도장/법원 느낌은 보조 장식으로 낮춘다.

### 3. 모바일 구조가 데스크톱 축소판에 가까움

문제:
- 오른쪽 패널이 아래로 밀리면서 리스트가 길어지고, 주요 행동을 찾기 어렵다.
- 추천 후 유사 메뉴, 기록, 상태 칩이 세로로 쌓여 피로감이 생긴다.

개선:
- 모바일은 별도 레이아웃으로 본다.
- 메인 카드 + 하단 액션바 + 바텀시트 상태 선택 + 접힌 기록 패널 구조가 더 적합하다.

### 4. 데이터 기능이 시각적으로 설득되지 않음

문제:
- 프로필/지역/기록 기능이 생겼지만 아직 화면에서 “왜 의미 있는지”가 약하다.
- 지역 통계가 나중에 중요해질 수 있는데, 지금은 메뉴 결정과 직접 연결되지 않는다.

개선:
- 개인 기록은 `어제 김치찌개`, `3일 전 돈카츠`처럼 짧게 보여준다.
- 지역 통계는 `여의도 오늘 많이 고른 메뉴`처럼 보조 카드로 작게 시작한다.
- 추천 카드의 근거는 선택 조건과 음식 속성의 매칭으로 보여준다.

## 리디자인 방향

### 방향 A: 모바일 앱 같은 결정 화면

컨셉:
- “점심 고민 끝내기”에 집중한 모바일 우선 UI.

화면:
- 상단: 브랜드, 프로필, 지역
- 중앙: 오늘 메뉴 카드
- 카드 안: 메뉴명, 한 줄 카피, 키워드, 조건 매칭
- 하단: `이걸로 결정`, `오늘은 아님`, `다른 메뉴`
- 상태 선택: 바텀시트
- 기록: 아래 접힌 패널

장점:
- 가장 구현 가능성이 높다.
- 지금 기능과 잘 맞는다.
- 모바일 문제가 바로 줄어든다.

### 방향 B: 밥픽/점메추 스타일 캐주얼 앱

컨셉:
- 어린 사용자에게 더 맞는 가벼운 추천 서비스.
- 이름 후보: `밥픽`, `점메추`, `오늘밥`, `점심픽`, `먹킷`, `밥결정`.

화면:
- 큰 음식명
- 상태 이모지/아이콘성 칩
- 짧고 웃긴 음식별 카피
- 기록은 streak나 캘린더처럼 가볍게 표현

장점:
- 공유하기 좋고 기억에 남는다.
- 판결소보다 확장성이 좋다.

주의:
- 너무 귀여워지면 직장인 서비스 신뢰감이 떨어질 수 있다.

### 방향 C: 지역 데이터 기반 점심 큐레이션

컨셉:
- 개인 기록 + 지역 랭킹 + 추천이 합쳐진 서비스.

화면:
- 오늘 내 추천
- 우리 동네 픽
- 내 점심 캘린더
- 조건별 인기 메뉴

장점:
- 나중에 DB/Supabase 연결 후 데이터 서비스로 확장하기 좋다.

주의:
- 지금 단계에서 이 화면을 전면에 내세우면 핵심 행동이 흐려질 수 있다. MVP 화면에서는 보조로 두는 편이 낫다.

## 다음 디자인 작업 기준

### 레이아웃

- 모바일을 먼저 설계하고 데스크톱을 확장한다.
- 첫 화면에는 카드 1개, 주요 CTA 1개, 보조 CTA 1~2개만 둔다.
- 긴 리스트는 기본 노출하지 않는다. 필요하면 접힌 패널이나 바텀시트로 보낸다.
- 우측 패널은 데스크톱에서만 보조 정보로 사용한다.

### 타이포그래피

- 메뉴명은 크고 강하게, 설명은 짧게.
- 버튼 안 텍스트는 1~5단어 수준으로 줄인다.
- 카드 안 문장은 2줄을 넘기지 않는다.
- 모바일에서 제목이 버튼이나 칩과 겹치지 않게 고정 높이와 줄바꿈 기준을 둔다.

### 컬러

- 브랜드 컬러 1개, 행동 컬러 1개, 보조 컬러 2~3개로 제한한다.
- 추천 CTA는 항상 같은 계열로 유지한다.
- 음식 서비스이므로 차가운 회색보다 따뜻한 배경을 쓰되, 베이지 단색으로만 밀지 않는다.
- 빨강/주황은 음식감과 긴급감을 주지만 과하면 배달앱 광고처럼 보일 수 있으니 포인트로만 쓴다.

### 컴포넌트

- 상태 선택은 칩 나열보다 바텀시트 + 그룹화가 적합하다.
- 예: `입맛`, `몸상태`, `상황`, `지갑`.
- 필터가 적용되면 추천 카드 상단에 `중식 · 해장 · 매움 · 법카`처럼 압축해서 보여준다.
- 결정 버튼은 한 화면에서 가장 눈에 띄어야 한다.
- `오늘은 아님`은 파괴적 행동에 가깝기 때문에 보조 버튼으로 둔다.

### 모션

- 모션은 “랜덤 뽑기” 순간에만 짧게 쓴다.
- 음식 카드가 바뀔 때 살짝 밀리거나 뒤집히는 정도가 적당하다.
- 반복되는 장식 모션은 피한다.

### 카피

- 앱 설명을 길게 쓰지 말고 행동을 말한다.
- 나쁜 예: `오늘 점심 상태를 알려주면 더 정확히 골라드려요`
- 좋은 예: `지금 입맛부터 찍고 가자`
- 나쁜 예: `오늘의 추천 후보 TOP`
- 좋은 예: `내가 최근 먹은 것`, `우리 동네 픽`, `이 메뉴가 나온 이유`

## 추천 정보 구조

모바일 첫 화면:

1. 헤더
   - 브랜드명
   - 지역/프로필 작은 버튼

2. 상태 요약
   - `아무거나` 또는 `중식 · 해장 · 매움`
   - `상태 바꾸기`

3. 메뉴 결정 카드
   - 메뉴명
   - 음식 카피
   - 감각 키워드
   - 조건 매칭 근거

4. 하단 액션
   - `이걸로 결정`
   - `다른 메뉴`
   - `오늘은 아님`

5. 접힌 보조 정보
   - 최근 기록
   - 근처에서 찾기
   - 지역 랭킹

데스크톱:

- 왼쪽/중앙: 모바일 첫 화면과 동일한 결정 영역
- 오른쪽: 개인 기록, 지역 랭킹, 최근 선택
- 상단 필터 영역은 줄이고, 상태 선택은 모달/바텀시트로 통일
